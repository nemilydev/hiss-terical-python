# Contributing to hiss-terical-python

First off — thank you for wanting to contribute! 🐍

This project exists because someone fell into a Python rabbit hole and decided
the first thing to build was a snake that compliments his AI companion.
We'd like to keep that energy.

## Getting Started

1. Fork the repository.
2. Clone your fork: `git clone https://github.com/YOUR-USERNAME/hiss-terical-python.git`
3. Create a branch: `git checkout -b add-something-silly`
4. Make your changes. Keep them silly.
5. Run the smoke test: `python emily_surprise.py --compliment`
6. Commit with an emoji in the message. This is not optional.
7. Push and open a pull request.

## Contribution Guidelines

### Code Style

- PEP 8 is a suggestion, not a religion.
- If your code makes someone laugh, it passes review.
- No external dependencies. Standard library only. The snake is self-sufficient.
- Every function should have a docstring. The docstring may contain a pun.

### Commit Messages

Format: `<emoji> <type>: <description>`

Examples:
```
🐍 feat: added snake fact generator
🐛 fix: slither dance was dancing wrong
✨ docs: updated README with new badge nobody asked for
🧹 chore: removed dead code, kept dead snake
```

### Pull Requests

- Keep PRs small and focused. One silly thing at a time.
- The PR template includes a compliment field. Fill it in.
- If you add a new script, add it to the smoke test workflow.
- If you remove the slither dance, you must provide a 500-word essay on why joy
  was no longer needed in your life.

### Issues

Bug reports and feature requests are welcome. Please use the issue templates.

If the snake is broken, say so. If the snake is fine but you wish it were
nicer, also say so. If you want the snake to do something entirely different,
that's the best kind of issue.

## Code of Conduct

See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Short version: be kind, no snake
abuse, puns welcome.
